# FLASH STM32H723 — все регистры, все биты (включая резервные)

База `0x52002000`, один банк 1 Мбайт (сектора по 8 Кбайт). Сверено с `Inc/stm32h723xx.h`.
ECC на всей памяти: 1 ошибка правится, 2 — детектируются.
`res` = зарезервировано: не трогать, при чтении игнорировать.

## ACR (0x00) — задержки чтения, rw

| Биты | Имя | Что делает |
|---|---|---|
| 3:0 | LATENCY[3:0] | Wait states чтения: 0–15. Правило: +1 WS примерно на каждые 70 МГц HCLK (0WS до ~70, дальше по нарастающей). На 550 МГц ставь 7 (максимум осмысленного). Больше — всегда безопасно, меньше — сбои чтения. Ставить ДО разгона |
| 5:4 | WRHIGHFREQ[1:0] | Задержка сигналов записи/стирания: чем выше HCLK, тем больше. На 550 ставь 3 |
| 31:6 | res | Зарезервированы |

Наше эхо: `ACR = 7 | (3<<4) = 0x37`.

## KEYR1 (0x04) / OPTKEYR (0x08) — ключи разблокировки, w

Полные 32-битные регистры, побитовой структуры нет:

- Снять `CR1.LOCK`: записать `0x45670123`, затем `0xCDEF89AB` в KEYR1.
- Снять `OPTCR.OPTLOCK`: записать `0x08192A3B`, затем `0x4C5D6E7F` в OPTKEYR.
- После операций вернуть LOCK/OPTLOCK в 1.

## CR1 (0x0C) — управление операциями, rw (когда не BSY)

| Биты | Имя | Что делает |
|---|---|---|
| 0 | LOCK | 1=контроллер заперт (по сбросу 1). Снять ключами через KEYR1 |
| 1 | PG | 1=режим программирования (запись 256-битного слова кидает операцию) |
| 2 | SER | 1=режим стирания сектора (номер — SNB), запуск — START |
| 3 | BER | 1=стереть весь банк (mass erase), запуск — START |
| 5:4 | PSIZE[1:0] | Ширина программирования: 00=x8, 01=x16, 10=x32, 11=x64. Должна совпадать с реальной шириной записи, иначе PGSERR |
| 6 | FW | Форсированная запись: старт новой операции не дожидаясь конца предыдущей |
| 7 | START | 1=старт SER/BER/пользовательского CRC. Самоочищается |
| 10:8 | SNB[2:0] | Номер сектора для SER |
| 14:11 | res | Зарезервированы |
| 15 | CRC_EN | Разрешение CRC-модуля флеша |
| 16 | EOPIE | Прерывание по концу операции (EOP) |
| 17/18/19 | WRPERRIE/PGSERRIE/STRBERRIE | Прерывания по ошибкам защиты/последовательности/строба |
| 20 | res | Зарезервирован |
| 21/22 | INCERRIE/OPERRIE | Прерывания: несогласованность / ошибка операции |
| 23/24 | RDPERRIE/RDSERRIE | Прерывания: readout-защита / secure-ошибка |
| 25/26 | SNECCERRIE/DBECCERRIE | Прерывания: ECC поправил / ECC нашёл двойную |
| 27/28 | CRCENDIE/CRCRDERRIE | Прерывания: CRC готов / ошибка чтения CRC |
| 31:29 | res | Зарезервированы |

## SR1 (0x10) — статусы и ошибки, r (EOP и ошибки гасятся через CCR1)

| Биты | Имя | Что делает |
|---|---|---|
| 0 | BSY | 1=идёт операция. Пока висит — CR1 не трогать |
| 1 | WBNE | 1=буфер записи не пуст |
| 2 | QW | 1=очередь записи занята |
| 3 | CRC_BUSY | 1=считается CRC |
| 15:4 | res | Зарезервированы |
| 16 | EOP | Операция завершена (гасится CCR1) |
| 17 | WRPERR | Писали в защищённый сектор |
| 18 | PGSERR | Нарушена последовательность (не тот PSIZE, запись без PG и т.п.) |
| 19 | STRBERR | Ошибка строба программирования |
| 20 | res | Зарезервирован |
| 21 | INCERR | Несогласованность (например, запись по невыровненному адресу) |
| 22 | OPERR | Ошибка операции (в т.ч. при запертом контроллере/низком напряжении) |
| 23 | RDPERR | Сработала readout-защита |
| 24 | RDSERR | Secure-ошибка доступа |
| 25 | SNECCERR | ECC исправил одиночную ошибку (информационный) |
| 26 | DBECCERR | ECC нашёл двойную ошибку (данные битые) |
| 27 | CRCEND | CRC посчитан, результат в CRCDATA |
| 28 | CRCRDERR | Ошибка чтения при подсчёте CRC |
| 31:29 | res | Зарезервированы |

## CCR1 (0x14) — сброс флагов SR1, w1c

| Биты | Имя | Что делает |
|---|---|---|
| 15:0 | res | Зарезервированы |
| 16–28 чётные | CLR_* | Запись 1 гасит одноимённый флаг SR1: `CLR_EOP(16)`, `CLR_WRPERR(17)`, `CLR_PGSERR(18)`, `CLR_STRBERR(19)`, `CLR_INCERR(21)`, `CLR_OPERR(22)`, `CLR_RDPERR(23)`, `CLR_RDSERR(24)`, `CLR_SNECCERR(25)`, `CLR_DBECCERR(26)`, `CLR_CRCEND(27)`, `CLR_CRCRDERR(28)` |
| 20 | res | Зарезервирован |
| 31:29 | res | Зарезервированы |

Перед каждой операцией чистить старые ошибки.

## OPTCR (0x18) — опции, rw

## OPTSR_CUR (0x1C, ro) / OPTSR_PRG (0x20, rw) — байты опций

Текущие / записываемые. Биты (одинаковы в обоих):

| Биты | Имя | Что делает |
|---|---|---|
| 0 | OPT_BUSY | 1=пишутся опции, ждать 0 (актуально в CUR) |
| 1 | res | Зарезервирован |
| 3:2 | BOR_LEV[1:0] | Уровень brown-out reset |
| 4 | IWDG1_SW | 1=независимый watchdog управляется программой, 0=стартует сам |
| 5 | res | Зарезервирован |
| 6 | NRST_STOP_D1 | 0=вход в Stop сбрасывает D1, 1=Stop без сброса |
| 7 | NRST_STBY_D1 | 0=вход в Standby сбрасывает D1, 1=без сброса |
| 15:8 | RDP[7:0] | Readout-защита: `0xAA`=уровень 0 (открыто), другое=уровень 1, `0xCC`=уровень 2 (необратимо!) |
| 16 | res | Зарезервирован |
| 17 | FZ_IWDG_STOP | 1=IWDG стоит в Stop |
| 18 | FZ_IWDG_SDBY | 1=IWDG стоит в Standby |
| 20:19 | ST_RAM_SIZE[1:0] | Делёж shared-RAM между ITCM и AXI (кодировку смотри в RM0468) |
| 21 | SECURITY | 1=secure-режим устройства |
| 23:22 | res | Зарезервированы |
| 24 | NRST_STOP_D2 | То же для домена D2 в Stop |
| 25 | NRST_STBY_D2 | То же для D2 в Standby |
| 28:26 | res | Зарезервированы |
| 29 | IO_HSLV | 1=быстрые пины даже при пониженном VDD |
| 30 | OPTCHANGEERR | Ошибка смены опций (гасится OPTCCR) |

## CRCCR1 (0x50) / CRCSADD1 (0x54) / CRCEADD1 (0x58) / CRCDATA (0x5C) — CRC флеша

| Биты | Имя | Что делает |
|---|---|---|
| 2:0 | CRC_SECT[2:0] | Номер сектора для посекторного CRC |
| 7:3 | res | Зарезервированы |
| 8 | CRC_BY_SECT | 1=считать по секторам (иначе по диапазону адресов) |
| 9 | ADD_SECT | 1=добавить сектор к текущему расчёту |
| 10 | CLEAN_SECT | 1=сбросить посекторный аккумулятор |
| 15:11 | res | Зарезервированы |
| 16 | START_CRC | 1=старт расчёта |
| 17 | CLEAN_CRC | 1=сбросить результат |
| 19:18 | res | Зарезервированы |
| 21:20 | CRC_BURST[1:0] | Размер burst чтения при расчёте |
| 22 | ALL_BANK | 1=весь банк целиком |
| 31:23 | res | Зарезервированы |

CRCSADD1/CRCEADD1/CRCDATA — полные 32-битные (адрес начала/конца по словам,
CRCDATA = ro-результат, готовность — SR1.CRCEND).
Применение: задать диапазон → `START_CRC=1` → ждать `CRCEND` → сверить `CRCDATA`
с эталоном (самопроверка прошивки).

## Как программировать флеш из кода (алгоритм)

1. Дождаться `BSY=0`, почистить старые ошибки через CCR1.
2. Снять LOCK ключами (`0x45670123`, `0xCDEF89AB`).
3. Стирание сектора: `SER=1`, `SNB=N`, `START=1`, ждать `BSY=0`/`EOP`.
   Mass erase: то же с `BER=1`.
4. Запись: `PG=1`, `PSIZE` под ширину, писать словами по адресу,
   ждать `BSY=0`/`EOP` после каждого.
5. Вернуть `LOCK=1`. Ошибки разбирать по SR1 (WRPERR/PGSERR/OPERR...).
