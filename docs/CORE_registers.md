# CORE — ядро Cortex-M7 (STM32H723VGT6)

NVIC, SCB, SysTick, CPACR, FPU. Сверено с `Inc/core_cm7.h`
(структуры `NVIC_Type`, `SCB_Type`, `SysTick_Type`, `FPU_Type`,
маски `SCB_*/SysTick_*/NVIC_*/FPU_*_Pos`).
`__NVIC_PRIO_BITS = 4` (переопределено в `Inc/stm32h723xx.h:216`,
в `core_cm7.h` по умолчанию 3 — для H723 верно 4).

## Базовые адреса (из `core_cm7.h`)

`SCS_BASE = 0xE000E000` (System Control Space).

| Блок | База | Формула |
|------|------|---------|
| SysTick | 0xE000E010 | `SCS_BASE + 0x0010` |
| NVIC | 0xE000E100 | `SCS_BASE + 0x0100` |
| SCB | 0xE000ED00 | `SCS_BASE + 0x0D00` |
| FPU | 0xE000EF30 | `SCS_BASE + 0x0F30` |

## NVIC — контроллер прерываний

8 слов × 32 бита = до 256 внешних IRQ. Номер слова = `IRQn >> 5`,
бит = `IRQn & 0x1F` (см. функции `NVIC_EnableIRQ` и др. в `core_cm7.h`).

| Смещение | Регистр | Доступ | Назначение |
|----------|---------|--------|------------|
| 0x000 + 4*i, i=0–7 | ISER[8] | R/W | Set-Enable: запись 1 разрешает IRQ |
| 0x080 + 4*i | ICER[8] | R/W | Clear-Enable: запись 1 запрещает IRQ |
| 0x100 + 4*i | ISPR[8] | R/W | Set-Pending: запись 1 ставит пендинг |
| 0x180 + 4*i | ICPR[8] | R/W | Clear-Pending: запись 1 снимает пендинг |
| 0x200 + 4*i | IABR[8] | R/W | Active: 1 — обработчик выполняется |
| 0x300 + i, i=0–239 | IP[240] | R/W | Приоритет IRQn (1 байт на IRQ) |
| 0xE00 | STIR | W | Программный запуск IRQ по номеру |

Между блоками — `res` (`RESERVED0–RESERVED5`).

ISER/ICER/ISPR/ICPR/IABR: в каждом слове биты 31:0 — IRQ `32*i … 32*i+31`,
семантика «запись 1 действует, запись 0 без эффекта», чтение показывает
состояние. Отдельной таблицы не нужно — все 32 бита значимые, `res` нет.

| Биты (ISERi/ICERi/ISPRi/ICPRi/IABRi) | Имя | Что делает |
|------|-----|------------|
| 0–31 | SETENA/CLRENA/SETPEND/CLRPEND/ACTIVE (IRQ 32i+0 … 32i+31) | Разрешить/запретить/поднять/снять/активность (по 1 биту) |

IP[240]: 1 байт на прерывание, используются только старшие
`__NVIC_PRIO_BITS = 4` бита (биты 7:4), младшие 3:0 — `res` (игнорируются).

### STIR (NVIC, 0xE00) — программный триггер (только запись)

| Биты | Имя | Что делает |
|------|-----|------------|
| 8:0 | INTID[8:0] | Номер прерывания для запуска (`NVIC_STIR_INTID_Msk = 0x1FF`) |
| 31:9 | `res` | Резерв |

## SCB — системный блок управления (база 0xE000ED00)

| Смещение | Регистр | Доступ | Назначение |
|----------|---------|--------|------------|
| 0x000 | CPUID | R | ID процессора |
| 0x004 | ICSR | R/W | Управление прерываниями и состояние |
| 0x008 | VTOR | R/W | Смещение таблицы векторов |
| 0x00C | AIRCR | R/W | Сброс, группы приоритетов (ключ 0x05FA) |
| 0x010 | SCR | R/W | Сон (SLEEPDEEP, SLEEPONEXIT…) |
| 0x014 | CCR | R/W | Конфигурация (выравнивание, деление на 0, кэши) |
| 0x018–0x023 | SHPR[12] | R/W | Приоритеты системных обработчиков 4–15 (12 байт) |
| 0x024 | SHCSR | R/W | Включение/состояние системных fault-обработчиков |
| 0x028 | CFSR | R/W | Флаги MemManage/BusFault/UsageFault (w1c) |
| 0x02C | HFSR | R/W | Флаги HardFault (w1c) |
| 0x030 | DFSR | R/W | Флаги отладки (w1c) |
| 0x034 | MMFAR | R/W | Адрес ошибки MemManage |
| 0x038 | BFAR | R/W | Адрес ошибки BusFault |
| 0x03C | AFSR | R/W | Вспомогательный статус (implementation defined, битовых define в `core_cm7.h` нет) |
| 0x040–0x06C | ID_PFR/DFR/AFR/MFR/ISAR | R | Feature-регистры (без битовых define) |
| 0x078–0x084 | CLIDR/CTR/CCSIDR/CSSELR | R/RW | Кэш: уровни, тип, выбор |
| 0x088 | CPACR | R/W | Доступ к сопроцессорам CP10/CP11 (FPU) |
| 0x200 | STIR (SCB) | W | Алиас программного триггера (`SCB_STIR_INTID`, 8:0) |
| 0x240–0x248 | MVFR0–2 | R | Feature-регистры FPU |
| 0x250–0x27C | ICIALLU…BPIALL | W | Инвалидация кэшей/BP (по 1 регистру на операцию) |

### CPUID (0x000)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:24 | IMPLEMENTER | Производитель (ARM = 0x41) |
| 23:20 | VARIANT | Вариант ревизии |
| 19:16 | ARCHITECTURE | Архитектура (Cortex-M7 = 0xF) |
| 15:4 | PARTNO | Номер (M7 = 0xC27) |
| 3:0 | REVISION | Патч-ревизия |

### ICSR (0x004)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31 | NMIPENDSET | 1 — NMI в пендинге (запись 1 ставит, чтение — статус) |
| 30:29 | `res` | Резерв |
| 28 | PENDSVSET | Запись 1 — вызвать PendSV |
| 27 | PENDSVCLR | Запись 1 — снять PendSV |
| 26 | PENDSTSET | Запись 1 — вызвать SysTick |
| 25 | PENDSTCLR | Запись 1 — снять SysTick |
| 24 | `res` | Резерв |
| 23 | ISRPREEMPT | 1 — прерыванию грозит вытеснение (только чтение) |
| 22 | ISRPENDING | 1 — есть пендинг внешнего IRQ (только чтение) |
| 21:12 | VECTPENDING[8:0] | Номер высшего пендинга (только чтение) |
| 11 | RETTOBASE | 1 — нет вложенных активных прерываний |
| 10:9 | `res` | Резерв |
| 8:0 | VECTACTIVE[8:0] | Номер выполняющегося исключения (0 = thread) |

### VTOR (0x008)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:7 | TBLOFF | Смещение таблицы векторов (`SCB_VTOR_TBLOFF_Msk = 0x1FFFFFF << 7`) |
| 6:0 | `res` | Резерв (выравнивание на 128 байт) |

### AIRCR (0x00C) — запись только с VECTKEY=0x05FA в битах 31:16

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:16 | VECTKEY / VECTKEYSTAT | Ключ записи 0x05FA / ключ чтения |
| 15 | ENDIANESS | Порядок байт (только чтение) |
| 14:11 | `res` | Резерв |
| 10:8 | PRIGROUP[2:0] | Разбиение приоритетов на группу/подгруппу |
| 7:3 | `res` | Резерв |
| 2 | SYSRESETREQ | Запись 1 — системный сброс |
| 1 | VECTCLRACTIVE | Запись 1 — сбросить активные состояния (отладка) |
| 0 | VECTRESET | Запись 1 — сброс процессора (отладка) |

### SCR (0x010)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:5 | `res` | Резерв |
| 4 | SEVONPEND | 1 — выход из сна по любому пендингу |
| 3 | `res` | Резерв |
| 2 | SLEEPDEEP | 1 — Stop/Standby вместо Sleep (глубокий сон) |
| 1 | SLEEPONEXIT | 1 — спать сразу при выходе из обработчика |
| 0 | `res` | Резерв |

### CCR (0x014)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:19 | `res` | Резерв |
| 18 | BP | 1 — разрешить предсказание ветвлений |
| 17 | IC | 1 — разрешить I-кэш |
| 16 | DC | 1 — разрешить D-кэш |
| 15:10 | `res` | Резерв |
| 9 | STKALIGN | 1 — выравнивать стек на 8 байт при входе (всегда 1 в M7) |
| 8 | BFHFNMIGN | 1 — игн. BusFault/HardFault в NMI/fault-обработчиках |
| 7:5 | `res` | Резерв |
| 4 | DIV_0_TRP | 1 — fault при делении на 0 |
| 3 | UNALIGN_TRP | 1 — fault при невыровненному доступу |
| 2 | `res` | Резерв |
| 1 | USERSETMPEND | 1 — непривилегированному коду разрешён STIR |
| 0 | NONBASETHRDENA | 1 — вход в thread без возврата в handler |

### SHPR (0x018–0x023) — приоритеты системных исключений

12 байт (`SHPR[12U]`): байт i = приоритет исключения 4+i.
Используются старшие 4 бита каждого байта (как в NVIC IP).
Карта: SHPR[0–2] — исключения 4–6 (`res`), SHPR[3] — MemManage (7),
SHPR[4] — BusFault (8), SHPR[5] — UsageFault (9), SHPR[6–7] — исключения
10–11 (`res`), SHPR[8] — SVCall (12), SHPR[9] — DebugMonitor (13),
SHPR[10] — PendSV (14), SHPR[11] — SysTick (15).

|------|-----|------------|
| 31:19 | `res` | Резерв |
| 18 | USGFAULTENA | 1 — разрешить UsageFault |
| 17 | BUSFAULTENA | 1 — разрешить BusFault |
| 16 | MEMFAULTENA | 1 — разрешить MemManage |
| 15 | SVCALLPENDED | Пендинг SVCall |
| 14 | BUSFAULTPENDED | Пендинг BusFault |
| 13 | MEMFAULTPENDED | Пендинг MemManage |
| 12 | USGFAULTPENDED | Пендинг UsageFault |
| 11 | SYSTICKACT | Активен обработчик SysTick |
| 10 | PENDSVACT | Активен PendSV |
| 9 | `res` | Резерв |
| 8 | MONITORACT | Активен DebugMonitor |
| 7 | SVCALLACT | Активен SVCall |
| 6:4 | `res` | Резерв |
| 3 | USGFAULTACT | Активен UsageFault |
| 2 | `res` | Резерв |
| 1 | BUSFAULTACT | Активен BusFault |

### CFSR (0x028) — три байта статусов (сброс записью 1)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:26 | `res` | Резерв |
| 25 | DIVBYZERO | Деление на 0 (UFSR) |
| 24 | UNALIGNED | Невыровненный доступ (UFSR) |
| 23:20 | `res` | Резерв |
| 19 | NOCP | Нет сопроцессора (UFSR) |
| 18 | INVPC | Неверный EXC_RETURN (UFSR) |
| 17 | INVSTATE | Недопустимое состояние (UFSR) |
| 16 | UNDEFINSTR | Неизвестная инструкция (UFSR) |
| 15 | BFARVALID | BFAR содержит верный адрес (BFSR) |
| 14 | `res` | Резерв |
| 13 | LSPERR | Ошибка lazy-сохранения FP при BusFault |
| 12 | STKERR | Ошибка стека при BusFault |
| 11 | UNSTKERR | Ошибка распаковки стека при BusFault |
| 10 | IMPRECISERR | Неточная ошибка шины |
| 9 | PRECISERR | Точная ошибка шины |
| 8 | IBUSERR | Ошибка шины команд |
| 7 | MMARVALID | MMFAR содержит верный адрес (MMFSR) |
| 5 | MLSPERR | Ошибка lazy-сохранения FP при MemManage |
| 4 | MSTKERR | Ошибка стека при MemManage |
| 3 | MUNSTKERR | Ошибка распаковки стека при MemManage |
| 2 | `res` | Резерв (бит 2 MMFSR зарезервирован) |
| 1 | DACCVIOL | Нарушение доступа к данным |
| 0 | IACCVIOL | Нарушение доступа к коду |

При чтении видны как одно слово: UFSR = биты 31:16, BFSR = 15:8,
MMFSR = 7:0. В MMFSR бит 2 — `res`; в BFSR бит 14 — `res`.

### HFSR (0x02C)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31 | DEBUGEVT | Отладочное событие (w1c) |
| 30 | FORCED | Fault поднят до HardFault (w1c) |
| 29:2 | `res` | Резерв |
| 1 | VECTTBL | Ошибка чтения таблицы векторов (w1c) |
| 0 | `res` | Резерв |

### DFSR (0x030)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:5 | `res` | Резерв |
| 4 | EXTERNAL | Внешний отладчик (w1c) |
| 3 | VCATCH | Сработал vector catch (w1c) |
| 2 | DWTTRAP | Сработал DWT-триггер (w1c) |
| 1 | BKPT | Сработал breakpoint (w1c) |
| 0 | HALTED | Ядро остановлено (только чтение) |

### MMFAR (0x034) / BFAR (0x038) / AFSR (0x03C)

MMFAR/BFAR — 32-битный адрес ошибки (значимы при MMARVALID/BFARVALID).
AFSR — вспомогательный статус, битовых define в `core_cm7.h` нет
(implementation defined, на H7 обычно не используется).

### CPACR (0x088) — доступ к сопроцессорам

Битовых `_Pos/_Msk` define в `core_cm7.h` нет — позиции стандартные ARMv7-M:

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:24 | `res` | Резерв |
| 23:22 | CP11 | Доступ к CP11 (FPU, старшая половина): 00 — запрет, 11 — полный |
| 21:20 | CP10 | Доступ к CP10 (FPU): 00 — запрет, 11 — полный |
| 19:0 | `res` | Резерв |

Включение FPU (bare-metal): `SCB->CPACR |= (0xF << 20)` (CP10=CP11=11),
затем `DSB + ISB`.

## SysTick — системный таймер (база 0xE000E010)

24-битный счётчик вниз от LOAD до 0, флаг COUNTFLAG, прерывание SysTick_IRQn.

| Смещение | Регистр | Доступ | Назначение |
|----------|---------|--------|------------|
| 0x000 | CTRL | R/W | Управление и статус |
| 0x004 | LOAD | R/W | Перезагрузка (биты 23:0) |
| 0x008 | VAL | R/W | Текущее значение (запись обнуляет) |
| 0x00C | CALIB | R | Калибровка (TENMS, SKEW, NOREF) |

### CTRL (0x000)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:17 | `res` | Резерв |
| 16 | COUNTFLAG | 1 — досчитал до 0 (сбрасывается чтением) |
| 15:3 | `res` | Резерв |
| 2 | CLKSOURCE | 1 — ядро (HCLK), 0 — внешний/2 (NOREF) |
| 1 | TICKINT | 1 — разрешить прерывание SysTick |
| 0 | ENABLE | 1 — запустить счётчик |

### LOAD (0x004) / VAL (0x008)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:24 | `res` | Резерв |
| 23:0 | RELOAD / CURRENT | Значение перезагрузки / текущее (маска `0xFFFFFF`) |

### CALIB (0x00C)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31 | NOREF | 1 — внешнего клока нет |
| 30 | SKEW | 1 — калибровка на 10 мс неточна |
| 29:24 | `res` | Резерв |
| 23:0 | TENMS | Тактов на 10 мс (0 — калибровки нет) |

Настройка тика 1 мс при HCLK=hhhh: `LOAD = hhhh/1000 − 1`,
`VAL = 0`, `CTRL = CLKSOURCE | TICKINT | ENABLE`.

## FPU — блок плавающей точки (база 0xE000EF30)

| Смещение | Регистр | Доступ | Назначение |
|----------|---------|--------|------------|
| 0x000 | FPCCR | R/W | Управление контекстом FP (ASPEN/LSPEN/готовности) |
| 0x004 | FPCAR | R/W | Адрес незавершённого FP-контекста |
| 0x008 | FPDSCR | R/W | Дефолтный статус/контроль FP |

### FPCCR (0x000)

| Биты | Имя | Что делает |
|------|-----|------------|
| 31 | ASPEN | Автосохранение FP-контекста при исключении |
| 30 | LSPEN | Lazy-сохранение FP-контекста |
| 29:9 | `res` | Резерв |
| 8 | MONRDY | 1 — Monitor готов использовать FP |
| 7 | `res` | Резерв |
| 6 | BFRDY | 1 — BusFault готов (не отложен из-за FP) |
| 5 | MMRDY | 1 — MemManage готов |
| 4 | HFRDY | 1 — HardFault готов (приоритет выше FP-контекста) |
| 3 | THREAD | 1 — обработчик в thread-режиме может польз. FP |
| 2 | `res` | Резерв |
| 1 | USER | 1 — непривилегированный код может польз. FP |
| 0 | LSPACT | Активно lazy-сохранение (только чтение) |

### FPCAR (0x004) / FPDSCR (0x008)

FPCAR: биты 31:3 — ADDRESS (адрес FP-контекста в стеке), 2:0 — `res`.
FPDSCR:

| Биты | Имя | Что делает |
|------|-----|------------|
| 31:27 | `res` | Резерв |
| 26 | AHP | Альтернативный half-precision |
| 25 | DN | Default NaN |
| 24 | FZ | Flush-to-zero |
| 23:22 | RMode[1:0] | Режим округления |
| 21:0 | `res` | Резерв |
